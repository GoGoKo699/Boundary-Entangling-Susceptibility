# Reproduction

Use Python 3.11 or later. The recorded plotting environment is pinned in `requirements-reproducible.txt`; numerical comparisons allow explicit floating-point tolerances rather than asserting identical binary metadata across platforms.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-reproducible.txt
pip install -e .
python verify.py
pytest -q
```

The root data bundle is required and hash-checked. An incomplete clone must not be described as self-contained.

## 1. Redraw the accepted panels

```bash
python reproduce.py --core-figures
```

Six PDF/PNG/SVG triples are generated in a fresh temporary directory, validated, and copied to `reproduced_figures/`. No tracked plot is overwritten. The Figure 4 distance panel uses original means and intervals, with no exponential curve or fitted-length annotation. No TeX installation is used.

## 2. Regenerate and independently replay the current Figure 1 intervals

```bash
python scripts/analysis/complete_figure1_uncertainty.py --output reproduced_figure1_uncertainty
python scripts/analysis/verify_figure1_uncertainty.py --output reproduced_figure1_uncertainty --report figure1_review_verification/independent_replay.json
python scripts/analysis/check_figure1_adoption.py --resamples reproduced_figure1_uncertainty
```

Use an empty output directory. All proposals and retained contrasts are saved; both the primary recipe and the specified sensitivity are reproduced. The final command binds the outputs to the active panel. See [the adopted procedure](FIGURE1_UNCERTAINTY.md). This is a new calculation, not recovery of the missing historical resamples.

## 3. Replay the core numbers from stored records

```bash
python scripts/analysis/reproduce_core_records.py --output reproduced_records
```

This recalculates the ten unchanged Figure 1 point estimates and separately checks the historical interval table against its recovered hybrid source. The current Figure 1 intervals are fully regenerated by step 2; the missing historical resamples are not claimed recovered. It reconstructs Figure 2's representative code-probability slopes from state records, all 16 Figure 3 finite-size coefficients, and both Figure 4 endpoint estimates and distance means. It separately checks plotted archived intervals against the stored original arrays/tables. The output says which values were newly calculated and which interval calculations reuse archived resamples.

## 4. Repeat the September evidence reassessment

```bash
python scripts/analysis/reassess_evidence.py \
  --output reproduced_evidence --bootstrap 5000 --seed 2026090501
```

The default input is the in-repository bundle. The former `--archive original_checkpoint_05.zip` interface remains supported for provenance comparisons but is not required. This is the same estimator and selection logic as the audited September reassessment; only the source-container adapter changed.

It recalculates the stored-row point coefficients and paired endpoints, applies the explicitly post-hoc same-side and common-eligibility checks, and repeats the fit-residual and size-sensitivity calculations. New location intervals use whole-pre-state resampling. Size-model intervals reuse the archived size-level resamples. These sensitivity results do not replace the frozen primary data.

## 5. Materialize a research workspace and run simulator checks

```bash
python materialize_studies.py --output reproduced_studies
python studies/checkpoint_05/scripts/validate_tableau_against_statevector.py \
  --clifford-table reproduced_studies/checkpoint_05/data/two_qubit_clifford_group.npz \
  --maps reproduced_studies/checkpoint_05/data/two_qubit_clifford_symplectic_maps.npz \
  --report reproduced_records/tableau_statevector.json
python studies/checkpoint_04/scripts/validate_gate_invariant_formula.py \
  --out reproduced_records/gate_invariants.json --samples 100 --seed 123
```

The workspace also contains the original intervention and full scaling input layouts. The [campaign recipes](CAMPAIGN_RECIPES.md) give explicit run labels, grids and base seeds and distinguish verified generation inputs from unavailable historical command/analysis-seed records. `--help` documents an interface, not proof of a historical invocation. Full generation is not run on every commit and was not repeated for the audit repairs.

## 6. Replay the supporting architecture/probe exports

```bash
python scripts/analysis/reproduce_supporting_records.py --output reproduced_supporting_records --check
```

This recomputes the retained compact endpoints and four-purity decompositions from the original included records, writes the source manifest and support table, and compares all current exports byte-for-byte. A discrepancy fails the command. Archived interval columns remain explicitly identified as historical bootstrap output; this is not a fresh extension bootstrap or a substitution for the adopted Figure 1 recipe. The [supporting-results guide](../studies/checkpoint_04/results/README.md) gives the exact estimand and the preserved inconsistent historical exports.

## Meaning of verification

Fast CI checks software, local references, source-data integrity, current artwork identity, and redraws. The record-replay job recalculates the frozen core statistics. It is not a second randomly seeded physical campaign or external replication. Extrapolation and causal-scope limitations remain in the [evidence reassessment](EVIDENCE_REASSESSMENT.md).

See [precise reproducibility limits](REPRODUCIBILITY_LIMITS.md). Preserved original intervals and fully regenerated intervals are not interchangeable.

The audit diagnostics under `audits/full-sanity-01/` target their frozen baseline. Active repair regressions are under `tests/`; do not reinterpret a preserved audit expected-failure assertion against repaired current files as evidence about the old baseline.
